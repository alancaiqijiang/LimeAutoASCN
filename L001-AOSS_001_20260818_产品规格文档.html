1. 背景与问题陈述（Problem Statement）

LimeAuto 将比亚迪、零跑、阿维塔、方程豹、现代（SKD）等中国品牌整车出口至伊朗、沙特、迪拜等市场。车辆售出后，售后维保与质保索赔环节目前完全依赖人工 + 分散工具（Excel、微信、WhatsApp、邮件），缺乏统一的数字化管理。

当海外某台车发生故障（例如：一台比亚迪车的电池包损坏），经销商（如 KTL）向 LimeAuto 发起质保索赔时，我们面临五个"看不清"：

  1. 看不清维保历史 —— 无法快速调取该车从出厂到当前的全部质保/维保记录，难以判断故障是否落在质保与保养范围内。
  2. 看不清索赔边界 —— 索赔范围、易损件排除、里程/年限限制等质保规则分散在合同与人脑里，容易超赔或漏赔。
  3. 看不清核销状态 —— 索赔审批与核销无流程留痕，靠人盯，容易遗漏、重复或延误。
  4. 看不清备件库存 —— 索赔通过后，从备件库发货靠人工登记，库存与发货进度不透明。
  5. 看不清配件信息 —— 已握有 BYD 售后的 OE 配件号与图片，但缺一套可查询、可检索、可关联到索赔与备件的 OE 目录体系。

不解决的代价： 质保赔付纠纷与多赔/漏赔带来的直接损失、经销商与终端客户满意度下降、备件库存积压或断供、售后团队人力成本持续放大，以及在多品牌扩张时售后管理进一步失控。

2. 目标（Goals）

用户目标（经销商/内部团队得到什么）

  • G1 任一车辆可 10 秒内调出完整质保/维保档案（VIN 或车牌一键检索）。
  • G2 索赔全流程线上化、可追踪，经销商能实时看到每一步状态，不再靠催问。
  • G3 备件库存与发货状态对经销商与内部双向透明。

业务目标（LimeAuto 得到什么）

  • G4 将单笔索赔从提交到核销的平均周期缩短 50%（从当前人工流程的 N 天缩短至 N/2 天），并实现 100% 留痕可审计。
  • G5 通过质保规则引擎减少 30% 以上超范围赔付（在 6 个月内）。
  • G6 备件发货及时率 ≥ 95%，索赔驳回原因 100% 可追溯。
  • G7 OE 配件查询库上线后，经销商自服务查件率 ≥ 70%（减少对内部售后的重复人工咨询）。

目标均为可衡量的结果（Outcome），而非"做一个系统"这类输出（Output）。

3. 非目标（Non-Goals）

明确 V1 不做 的内容，防止范围蔓延：

# 非目标 说明
N1 售前 CRM / 销售漏斗 / 询价报价 本系统聚焦"售出之后"；售前线索与报价已有其他方式管理
N2 财务总账 / 结算 / 打款 V1 只做索赔的"业务核销"，不做钱款账务；财务耦合预留接口，后续接入
N3 车辆远程诊断 / 车联网（OTA、远程读取车辆数据） 依赖车企开放能力，周期长、成本高，V1 仅支持人工录入故障与诊断信息
N4 完整 ERP（生产、采购、人事等） 本系统是售后垂直域系统，不做通用 ERP
N5 在线支付 / 经销商在线下单付款 备件出库先走线下商务确认，V1 不做支付网关
N6 经销商在线注册自助开户 V1 由 LimeAuto 内部为经销商开账号，防止未授权访问质保数据

4. 用户与角色（Personas & Roles）

4.1 角色矩阵

角色 端 权限摘要

经销商售后专员 经销商门户 建车、录维保、发起索赔、查 OE 配件、查备件进度

仓库物流、财务 角色为 P2（后续扩展），V1 通过数据模型预留扩展位。

4.2 权限原则

  • 机构数据隔离：经销商只能看自己机构名下的车辆与索赔，互不可见。
  • 品牌维度可访问性：同一经销商可能只代理部分品牌（如 AvaMotor 主要现代/零跑，KTL 主要比亚迪），系统按品牌授予数据可见性。
  • 最小权限 + 审批留痕：关键动作（审批、核销、发货）必须留痕，可审计。

5. 用户故事（User Stories）

按优先级排序。核心贯穿场景：海外一台比亚迪车电池包损坏 → 经销商 KTL 索赔 → 查质保 → 核销 → 备件发货。

P0（必须）： - 作为经销商售后专员，我希望用 VIN/车牌一键查询某台车的质保与维保档案，以便判断故障是否在质保范围内。 - 作为经销商售后专员，我希望在线提交质保索赔单（附故障描述、照片、诊断信息），以便 LimeAuto 能及时受理并给出结论。 - 作为 LimeAuto 索赔审核员，我希望看到索赔单自动关联的车辆质保状态、维保记录与质保规则，以便快速判定"是否赔付 / 赔多少"。 - 作为 LimeAuto 索赔审核员，我希望对索赔进行"通过 / 部分通过 / 驳回"的线上批复并留痕，以便结果可追溯。 - 作为 LimeAuto 售后管理员，我希望对已批复的索赔执行"核销"，并生成备件发货单，以便索赔闭环并驱动备件出库。 - 作为经销商售后专员，我希望在 OE 配件库按 OE 号 / 车型 / 关键词检索配件（含图片），以便自服务查件、减少反复咨询。 - 作为备件管理员，我希望查看备件库存并完成出库、发货、填写物流单号，以便经销商实时看到发货进度。

P1（重要）： - 作为经销商管理员，我希望查看本机构全部索赔的实时状态看板，以便统一跟进不再催问。 - 作为索赔审核员，我希望系统对"超里程/超年限/易损件"自动给出风险提示，以便减少人工漏判。 - 作为售后管理员，我希望将索赔单中的配件条目直接关联 OE 目录（自动带出图片、名称、替代件、价格），以便核销时快速生成发货明细。

P2（未来）： - 作为经销商，我希望以图搜图 / 上传实物照片反查配件，以便在仅有实物无编号时也能定位配件。 - 作为财务，我希望对核销后的索赔生成对账/结算汇总，以便与经销商对账。

6.1 M1 车辆档案与维保记录（Vehicle & Maintenance Records）

说明： 每台售出车辆建立唯一档案，作为索赔判断的事实基础。

P0： - 车辆主档：VIN（唯一键）、品牌、车系/车型、年款、配置、销售日期、出厂日期、质保起始日、经销商（所属机构）、终端客户信息（合规最小化）。 - 质保维度：整车质保期、三电质保期（电池/电机/电控，BYD 通常更长）、里程限制、特殊约定（如 SKD/平行出口差异）。 - 维保记录：每次保养/维修录入 —— 日期、里程、项目、机构、单据附件；支持经销商录入 + LimeAuto 补录。

P1： 维保记录批量导入（Excel）；保养到期/里程预警提醒。

验收标准（AC）： - [ ] 输入 VIN 可 1 次检索出该车完整档案与全部维保记录（含历史）。 - [ ] 车辆可绑定唯一经销商机构，机构间数据隔离。 - [ ] 维保记录支持附件上传（图片/PDF）且不可篡改（留痕）。

6.2 M2 质保索赔管理（Warranty Claim）

说明： 索赔全流程线上化，这是系统的主干。

P0： - 索赔单字段：索赔编号、关联车辆（自动带出质保信息）、故障描述、故障照片/视频、诊断信息、索赔配件（可关联 OE 目录）、索赔金额（若有）、期望处理方式（退换件/补发件/赔付）。 - 状态机（见第 7 章流程图）。 - 审批：审核员对"质保范围"判定，批复结果 = 通过 / 部分通过（改件/改额）/ 驳回，附理由。 - 规则引擎（V1 基础版）：自动校验 是否超里程 / 超年限 / 属易损件排除项，并高亮风险。

P1： 索赔附件 OCR/辅助识别；驳回原因模板化，便于统计分析。

验收标准（AC）： - [ ] 经销商可在线提交索赔，提交后自动生成唯一编号并进入待审队列。 - [ ] 审核员页面可看到该车质保状态与维保记录摘要，并完成三态批复，全程留痕。 - [ ] 状态流转中每一步都有通知（经销商门户站内信，P1 扩展邮件/WhatsApp）。 - [ ] 超里程/超年限/易损件 场景下系统给出明确风险提示。

6.3 M3 索赔核销（Claim Write-off / Settlement）

说明： 把"批复结论"落地为"可执行动作"，是索赔闭环的关键。

P0： - 核销动作：对已批复的索赔执行核销，生成"核销单"，明确赔付内容（配件补发 / 退换 / 金额冲抵）。 - 核销单自动生成备件发货需求，流转到 M4 备件库。 - 核销记录留痕：操作人、时间、批复依据、赔付明细。

P1： 部分核销（一次索赔分批核销）；核销与财务对账接口预留。

验收标准（AC）： - [ ] 只有"已批复（通过/部分通过）"的索赔才能被核销。 - [ ] 核销完成后索赔进入"已闭环"，且可在经销商端看到结果与发货信息。

6.4 M4 备件库与发货（Spare Parts Warehouse & Shipping）

说明： 库存可见 + 发货透明，支撑核销落地。

P0： - 库存：SKU（关联 OE 号）、当前库存量、库位、安全库存阈值。 - 出库：由核销单/补发单触发，扣减库存，生成出库单。 - 发货：填写物流单号、承运商、预计送达；经销商端可见进度。

P1： 安全库存预警、补货建议；发货物流状态自动抓取。

验收标准（AC）： - [ ] 核销后可在备件库直接生成出库单并扣减库存。 - [ ] 库存不足时系统提示，不允许负数出库。 - [ ] 发货后经销商端实时可见物流单号与状态。

6.5 M5 OE 配件查询库（OE Parts Catalog）

说明： 这是你最关心的模块。你已有 BYD OE 号与图片，缺的是"如何组织成可查询文档"的思路。详细设计见 第 8 章。

P0： - OE 目录数据模型 + 检索（按 OE 号 / 车型 / 系统树 / 关键词）。 - 配件详情页：图片（主图+角度图）、名称（中英）、适用车型、替代件号、交叉引用、质保类别、易损件标识。 - 与索赔、备件联动：索赔单配件条目可直接引用 OE 目录，自动带出图片/名称/替代件。

P1： 以图搜图；VIN 反查适用配件清单；价格/货期字段。

验收标准（AC）： - [ ] 输入 OE 号可精确命中配件并展示图片与属性。 - [ ] 可按"品牌 → 车系 → 系统 → 子系统 → 零件"层级浏览。 - [ ] 索赔单中选配件时能引用 OE 目录并回填信息。

6.6 M6 经销商门户（Dealer Portal）

说明： 海外经销商（英文界面）的入口。

P0： 登录、车辆列表、维保记录录入、索赔提交与状态查询、OE 配件查询、备件发货进度查看、本机构成员管理（管理员）。

P1： 索赔状态看板、通知中心。

6.7 M7 内部管理后台（Admin Console）

说明： LimeAuto 内部（英文界面）的运营中枢。

P0： 全量车辆/维保/索赔视图、索赔审核、核销、备件库存与发货、OE 目录维护、质保规则配置、经销商账号与品牌权限管理、操作审计日志。

6.8 M8 多品牌与规则引擎（Multi-brand & Rule Engine）

说明： 多品牌全覆盖的核心架构要求。

P0： - 所有核心实体（车辆、维保、索赔、OE、备件、质保规则）均带 品牌维度。 - 品牌字典 + 车系/车型字典可配置。 - 质保规则按"品牌 × 车系"配置（质保期、三电质保、里程限制、易损件清单）。

P1： 规则引擎进阶（组合条件、多级审批流、自动判定建议）。

P2： 品牌差异化工作流（不同品牌不同审批路径）。

7.2 质保索赔判断逻辑（核心决策）

判断"是否在质保范围内"按以下顺序：① 车辆身份 → ② 质保期限（时间+里程） → ③ 是否易损件/排除项 → ④ 是否人为/事故/私自改装 → ⑤ 是否在保养合规范围内（如脱保）。

系统在审核页以卡片形式汇总这 5 项，并给出"风险提示"，人工做最终判定。

7.3 备件发货流

核销单（赔付=补发配件）
   → 自动生成发货需求（关联 OE 配件 + 数量）
   → 备件库校验库存（不足则提示并挂起）
   → 出库（扣减库存，生成出库单）
   → 发货（填物流单号）
   → 经销商门户可见进度 → 确认收货 → 索赔 Closed

8.5 数据导入工具

  • 提供标准 Excel/CSV 导入模板（字段与 8.1 对齐）。
  • 支持批量导入 OE 号 + 图片：图片按 8.2 命名规范打包上传，系统按 OE 号自动关联。
  • 导入时自动校验 OE 号唯一性、重复件合并、替代关系建链。

8.6 与索赔/备件联动（关键价值）

  • 索赔单"索赔配件"条目 → 引用 OE 目录 → 自动带出图片、名称、替代件、质保类别、易损件标识。
  • 核销时"补发配件" → 直接引用 OE 目录 → 生成备件出库明细（SKU 关联 OE 号）。
  • 替代件处理：若索赔件停产，系统提示可用替代件号，减少呆滞。

8.7 数据维护与更新

  • 定期同步车企官方 EPC（电子零件目录）更新替代件关系。
  • 处理"老号停产 → 新号替代"链，避免查无此件。

9. 数据模型总览（Data Model）

核心实体关系：

Vehicle（车辆）──┬── MaintenanceRecord（维保记录）
                 └── WarrantyPolicy（质保规则，按品牌×车系）

Claim（索赔单）─── ClaimItem（索赔配件明细）─── oe_parts（OE 配件）

Claim ──► Writeoff（核销单）──► Shipment（发货）──► Inventory（备件库存，SKU→oe_no）

Dealer（经销商机构）── DealerUser（机构用户）
Brand ── Model ── Trim（品牌/车型/配置字典，贯穿全模块）

所有业务实体均带 brand 维度，满足多品牌覆盖；dealer 维度满足机构数据隔离。

11. 风险与依赖（Risks & Dependencies）

# 风险/依赖 影响 应对
R1 数据合规：车辆 VIN、终端客户个人信息跨境存储 高 遵循 GDPR / 中国《个人信息保护法》最小化收集，敏感字段加密，明确数据出境合规方案
R2 OE 数据准确性与版权：BYD EPC 数据授权 高 明确数据来源授权；替代件关系定期校验
R3 多品牌车型字典工作量大 中 分品牌分期接入（见第 12 章），先 BYD
R4 备件价格/汇率波动 中 价格作为可配置字段，不做硬编码
R5 经销商英文使用习惯差异 低 界面英文、操作引导 + 培训材料
R6 依赖车企质保政策口径 中 质保规则做成可配置，政策变化即时调整

12. 里程碑与分期（Phasing）

多品牌全覆盖按"先 BYD 打样 → 横向复制"分期推进，避免首版贪大。

阶段 内容 品牌 目标
Phase 1（V1） M1–M8 核心闭环（车辆/索赔/核销/备件/OE/门户/后台/规则基础版） BYD 打通"索赔→核销→发货"核心链路，跑通 OE 目录
Phase 2 横向接入其余品牌 + 规则引擎进阶 + 通知扩展（邮件/WhatsApp） 零跑 / 阿维塔 / 方程豹 / 现代SKD 多品牌可用
Phase 3 仓库物流、财务对账、以图搜图、VIN 反查、批量导入增强 全部 全链路 + 智能化
