1. 文档定位

本文档是把业务 PRD（L001-AOSS_001）落到 网页端 的规格说明，回答三个问题：

  1. 这个网站是什么（产品端口定位）
  2. 网站有哪些页面、每个页面做什么（信息架构 + 页面清单）
  3. 用户怎么在这些页面间完成核心任务（流程 + 权限）

本文档面向产品、设计、前端开发评审；技术实现细节（数据库、API、目录结构）见 L001-AOSS_003 技术架构文档。

2. 产品端口定位

LimeAuto After-Sales Portal 是一个面向 海外经销商 + LimeAuto 内部团队 的 Web 售后协同门户，用单一入口承载两个端：

端 使用者 核心目标
Dealer Portal（经销商门户） 海外经销商（KTL、AvaMotor、NekBar 等）售后人员 自服务：查车、录维保、提索赔、查配件、跟发货
Admin Console（内部后台） LimeAuto 内部（Alan/中方团队） 运营：审索赔、核销、管备件、维护 OE 与规则

定位原则： 本系统是「售后协同」而非「门户展示」，一切页面围绕 索赔闭环 与 配件自服务 设计；不做售前、不做营销内容。

形态： 桌面端优先的响应式 Web 应用，英文界面，浅色主题，业务数据密集型布局（表格 + 表单 + 状态看板）。

4. 页面清单与规格（Page Inventory & Spec）

状态：P0 = MVP 必备；P1 = 快速跟进；P2 = 后续。 每个页面列出：功能、关键组件、关键交互、权限。

4.1 通用（两个端共用）

页面 功能与组件 交互 优先级
Login 邮箱/账号 + 密码；「Remember me」；错误提示；登出后回跳 登录成功按角色路由（dealer→门户，admin→后台） P0

4.2 经销商门户（Dealer Portal）

页面 功能与组件 关键交互 优先级
D1 Dashboard 待办提示；索赔状态计数卡（Draft/Submitted/Under Review/Approved/Shipped）；最近车辆；快捷入口（新建索赔/查配件） 点击计数卡跳转对应筛选列表 P0
D2 Vehicles · List 车辆表格（VIN、品牌、车型、车牌、质保到期、状态）；搜索框（VIN/车牌）；分页 检索 + 点击行进入详情 P0
D3 Vehicles · Detail 车辆主档卡；质保档案卡（整车/三电期限+里程+剩余天数）；维保记录时间线；关联索赔列表 维保记录可展开附件；关联索赔可跳转 P0
D4 Claims · List 索赔表格（编号、车辆、故障、状态、日期）；状态筛选；状态徽章 筛选 + 点击进入详情/新建 P0
D5 Claims · New 分步表单：①选车（VIN 检索）②故障描述+照片上传+诊断信息 ③索赔配件（从 OE 目录选件）④确认提交 选车自动带出质保信息；选件引用 OE；提交进入待审 P0
D6 Parts Catalog 检索区（OE 号/关键词/品牌/车系树）；结果列表（缩略图+名称+OE 号）；配件详情（大图+属性+替代件+适用车型） 检索 + 系统树浏览 + 详情查看 P0
D7 Shipments 发货列表（核销单号、配件、物流单号、状态、预计送达） 点击查看详情 + 确认收货 P0

4.3 内部后台（Admin Console）

页面 功能与组件 关键交互 优先级
A1 Dashboard 待审队列计数；近 7 天索赔趋势；超范围赔付预警；快捷审核入口 点击待审进入审核列表 P0
A2 Claims Review 待审列表；审核详情页：质保判断卡片（①车辆身份 ②质保期限/里程 ③易损件排除 ④人为/事故 ⑤保养合规）+ 风险高亮；批复（通过/部分通过/驳回 + 理由） 逐项核对 + 三态批复 + 留痕 P0
A3 Write-off 已批复索赔列表；核销单生成（赔付内容：补件/退换/金额冲抵）；触发发货需求 核销确认 + 生成发货单 P0
A4 Parts & Inventory 库存表（SKU/OE 号、库存量、库位、阈值）；出库单；发货（物流单号录入） 出库扣减 + 发货 + 库存不足告警 P0
A5 OE Catalog Admin OE 目录表格；新增/编辑；批量导入（Excel + 图片包）；替代件关系维护 导入/编辑/替代件建链 P1
A6 Warranty Rules 规则列表（品牌×车系：整车质保、三电质保、里程限制、易损件清单） 增删改规则 P1
A7 Users & Access 经销商机构管理；用户账号；品牌授权（机构↔品牌可见性） 开账号/授权/停用 P0（最小版）

5. 关键用户流程（Key Flows）

5.1 登录与路由

输入账号密码 → 校验 → 成功：按角色路由
                       ├─ 经销商用户 → /dealer/dashboard
                       └─ 内部用户   → /admin/dashboard
                    → 失败：错误提示，留登录页

5.2 经销商提索赔（核心）

Dashboard/Claims → New Claim
  ① Select Vehicle（VIN 检索 → 选车，自动带出质保档案）
  ② Fault Description（故障描述 + 照片/视频上传 + 诊断信息）
  ③ Claim Parts（从 OE 目录选件，自动带出名称/图片/替代件）
  ④ Review & Submit（确认 → 生成索赔编号 → 状态=Submitted）

5.3 内部审核 → 核销 → 发货（核心闭环）

Admin Dashboard → Claims Review（待审队列）
  → 审核详情：质保判断卡片（5 项核对 + 风险高亮）
  → 批复：Approved / Partial / Rejected（附理由，留痕）
      ├─ 驳回 → 经销商可见原因，可修改重提
      └─ 通过/部分通过 → Write-off（核销）
            → 生成核销单（赔付内容）
            → 触发发货需求 → Parts & Inventory（出库扣减 → 发货填单号）
            → 经销商 Shipments 可见 → 确认收货 → 索赔 Closed

5.4 OE 配件查询（自服务）

Parts Catalog → 输入 OE 号/关键词 / 选品牌车系树浏览
  → 结果列表（缩略图）→ 配件详情（大图+属性+替代件+适用车型）
  → 可选「加入索赔配件」（跳转新建索赔并预填）

6. 权限与路由映射（RBAC & Routing）

路由前缀 角色可见 说明
/login 所有 统一登录
/dealer/* 经销商管理员 / 经销商售后专员 仅本机构数据
/admin/* 内部售后管理员 / 索赔审核员 / 备件管理员 / 系统管理员 全量数据

数据级权限（关键）： - 经销商只能访问 本机构（dealer_id） 名下的车辆、维保、索赔、发货。 - 品牌维度：经销商可见品牌 = 机构被授权的品牌集合（如 KTL 授权 BYD，AvaMotor 授权现代/零跑）。 - 内部角色按模块授权：审核员可审/批复，备件管理员可库存/发货，系统管理员可 OE/规则/账号。

7. 非功能需求（NFR）

维度 要求
性能 车辆/索赔列表首屏 < 2s；OE 检索响应 < 1s（数据量预期：OE 万级、车辆千级）
安全 HTTPS 全站；登录限流与防暴力破解；会话超时；关键操作（批复/核销/发货）二次留痕
响应式 桌面优先，平板可用；移动端仅保证查看可用（V1 不优化操作）
多语言 V1 英文；框架预留 i18n（未来可加波斯语/阿拉伯语/中文）
兼容 现代浏览器（Chrome/Safari/Edge 近 2 年版本）；不做 IE
可访问性 表单有 label、错误有明确提示、状态色配文字（不单靠颜色）

8. 页面状态规范

每个列表/详情页必须覆盖四态： - Loading：骨架屏/加载指示 - Empty：空态文案 + 引导动作（如"暂无索赔，点击新建"） - Error：错误提示 + 重试 - Data：正常数据渲染

9. MVP 页面优先级（小步快跑拆分）

迭代 0（跑通骨架，本次前端骨架已覆盖）： Login + Dealer Dashboard/Vehicles/Claims(New+List)/Parts Catalog + Admin Dashboard/Claims Review/Write-off/Parts Inventory。

迭代 1： Vehicles Detail 维保时间线、索赔详情页、发货确认收货、OE 详情替代件展示。

迭代 2： OE Catalog Admin 导入、Warranty Rules 配置、Users & Access 完整版、通知中心（站内信）。

迭代 3（P2）： 以图搜图、VIN 反查配件、财务对账、邮件/WhatsApp 通知、多语言。
