LimeAuto 售后经销商 OA 系统 — 技术架构文档（Technical Architecture）

Project ID: L001-AOSS_003　|　所属项目: L001-AOSS_001　|　版本: v1.0　|　日期: 2026-08-18 技术栈: HTML + AJAX + Laravel（PHP）+ MySQL 关联文档: L001-AOSS_001（业务 PRD）、L001-AOSS_002（网站需求）

1. 技术栈与选型理由

层 选型 版本建议 理由
前端 原生 HTML5 + CSS3 + JavaScript（fetch AJAX） — 轻量、无构建步骤，契合小步快跑；页面数有限，无需 SPA 框架
后端 Laravel 11.x（PHP 8.3+） 安全基座（ORM 防注入/CSRF/加密/会话）开箱即用；RBAC、审计、通知生态成熟；海外部署+英文友好
数据库 MySQL 8.0+（InnoDB） 生产标准、并发与事务支持，支撑多经销商 + 索赔事务闭环
鉴权 Laravel Sanctum — 前后端分离下用 Token 鉴权，经销商/内部统一登录
附件/图片 本地磁盘（V1）→ 对象存储（后续） — 索赔照片、OE 图片；V1 本地，规模上来再迁 OSS/S3

关键选型决策： 采用「前后端半分离」——前端为静态 HTML 页面，通过 AJAX 调 Laravel 的 JSON API；不用 SPA 框架、不引入前端构建链，降低上手与部署成本。

2. 系统架构（分层）

┌─────────────────────────────────────────────────────────────┐
│                    浏览器（Browser）                          │
│   Dealer Portal（/dealer/*）   Admin Console（/admin/*）      │
│   静态 HTML + CSS + JS（fetch AJAX）                          │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTPS / JSON（REST）
┌──────────────────────────▼──────────────────────────────────┐
│                    Laravel 应用（后端）                        │
│  路由 Route → 中间件 Auth/RBAC → 控制器 Controller           │
│        → 服务层 Service（业务规则/索赔状态机/质保校验）        │
│        → 模型 Model（Eloquent ORM）                           │
└──────────────────────────┬──────────────────────────────────┘
                           │ SQL
┌──────────────────────────▼──────────────────────────────────┐
│                     MySQL 8.0（InnoDB）                       │
│   vehicles / claims / oe_parts / inventory / shipments ...   │
└─────────────────────────────────────────────────────────────┘

原则： - 前端只做展示与交互，业务规则（质保判定、索赔状态机、库存扣减）全部在后端 Service 层，前端不承载关键逻辑。 - 所有数据读写走 AJAX JSON API，无页面级表单直提交（除登录可例外）。

4. 数据库设计（MySQL）

4.1 ER 关系（核心实体）

brands ──< models ──< trims
warranty_rules（品牌×车系 质保规则）

dealers ──< vehicles ──< maintenance_records（维保）

完整建表 DDL（含索引、外键、utf8mb4）见随附的 L001-AOSS_003_database.sql（如本轮选择产出，见交付说明）。

关键设计约定： - 所有表用 utf8mb4 字符集、InnoDB 引擎。 - 唯一约束：vehicles.vin、claims.claim_no、oe_parts.oe_no、inventory.sku。 - 金额用 DECIMAL(12,2)；里程用 INT（公里）；日期用 DATE，时间戳用 DATETIME。 - 软删除：deleted_at 用于 dealer/oe_parts 等，避免物理删除破坏历史索赔关联。

5. AJAX API 契约（REST 概要）

统一约定：Base /api；鉴权 Authorization: Bearer <token>；返回 JSON { success, data, message }；错误返回对应 HTTP 状态码 + message。

方法 端点 用途 权限
POST /api/login 登录换 token 公开
POST /api/logout 登出 登录
GET /api/vehicles 车辆列表（VIN/车牌检索，机构隔离） dealer/admin
GET /api/vehicles/{id} 车辆详情（含质保档案+维保+关联索赔） dealer/admin
POST /api/vehicles/{id}/maintenance 录入维保 dealer/admin
GET /api/claims 索赔列表（状态筛选） dealer（本机构）/admin（全量）
POST /api/claims 新建索赔 dealer
GET /api/claims/{id} 索赔详情（含质保判断摘要） dealer/admin
POST /api/claims/{id}/review 审核批复（approved/partial/rejected） 审核员
POST /api/claims/{id}/writeoff 核销（生成核销单+发货需求） 审核员/管理员
GET /api/oe-parts OE 检索（oe_no/关键词/品牌/车型树） dealer/admin
GET /api/oe-parts/{oe_no} OE 配件详情 dealer/admin
GET /api/inventory 备件库存列表 备件管理员/admin
POST /api/inventory/outbound 出库（扣减） 备件管理员
POST /api/shipments/{id}/tracking 录物流单号 备件管理员
POST /api/shipments/{id}/confirm 确认收货（经销商） dealer
GET /api/shipments 发货列表 dealer/admin

示例（新建索赔）：

POST /api/claims
{
  "vehicle_id": 1024,
  "fault_desc": "Battery pack failure, vehicle cannot charge",
  "diagnosis": "Error code BMS-0x07",
  "items": [{"oe_no":"BYD-BAT-8xxx","qty":1}]
}
→ 201 { "success":true, "data":{"claim_no":"CLM-2026-0001","status":"submitted"} }

6. 安全设计

项 方案
传输 全站 HTTPS；API 强制 TLS
认证 Sanctum Token（登录下发，前端存内存/localStorage）；登录限流（throttle）+ 失败锁定
授权 中间件层 RBAC + 机构隔离（dealer 只能查 dealer_id=自己）+ 品牌可见性过滤
注入 Eloquent ORM 参数化，禁止拼接 SQL
XSS 输出转义（Blade {{ }} / 前端 textContent）；上传文件白名单校验
CSRF API 走 Token 免 CSRF；如有 Cookie 场景用 Sanctum CSRF
上传 图片/PDF 白名单（MIME + 扩展名 + 大小限制）；重命名存储，禁止执行
审计 批复/核销/发货/账号变更写 audit_logs，含操作前后快照
合规 客户信息最小化收集；敏感字段加密；数据出境合规待法务确认（见 PRD 开放问题 Q5）

7. 部署架构

用户浏览器 ──HTTPS──▶ Nginx（静态资源 + 反代）
                         │  /         → public/*（静态前端）
                         │  /api/*    → PHP-FPM（Laravel）
                         ▼
                    PHP-FPM 8.3 ──▶ MySQL 8.0
  • 环境：单机起步（Nginx + PHP-FPM + MySQL 同机），规模上来再拆分 DB 独立/读写分离。
  • 版本管理：Git；.env 不入库，密钥用环境变量注入。
  • 备份：MySQL 每日自动备份 + 上传文件增量备份。
  • 监控：V1 用日志（Laravel Log）+ 错误通知；后续接入监控面板。
